# slide_editor — 投影片視覺編輯器

```bash
cd html-slide-builder

# 開一份新 deck：從起手式模板複製一份再編輯。不要直接開 examples/ ——
# 編輯器是就地寫檔，會把版控裡的範例改掉
mkdir -p decks/my-deck/slides
cp examples/starter/*.html decks/my-deck/slides/

python3 -m slide_editor.server decks/my-deck/slides
# 開 http://localhost:8765
```

也可以不指定 deck，直接用介面裡的「開啟」挑：

```bash
python3 -m slide_editor.server --root decks
```

`--root` 決定挑選器能瀏覽到哪裡（預設是 `<slides_dir>/../..`），伺服器端會擋掉
範圍外的路徑。

打包：

```bash
python3 build_deck.py decks/my-deck/slides \
        -o decks/my-deck/out/deck.html --font serif --nav scroll
```

---

## 唯一要記住的一件事

**編輯器直接寫進 `slides-*/` 的 HTML，那就是真相。** 改完即所見，不必重跑
theme、不必重新打包。

```
deck.json      ← 哪一個資料夾是活的
slides-*/      ← 真相。編輯器讀它、寫它
assets/        ← 插入的圖片影片
out/*.html     ← 要分享時才打包（字體內嵌成單一檔案）
.editor-backup/← 每頁第一次被改動前的原檔
.archive/      ← 已停用的舊 scaffolding，沒有程式會讀
```

deck 裡沒有任何會產生 slide 的程式，所以也沒有「重跑一次就把編輯蓋掉」這回事。
要換樣式，就另外做一份 `slides-<名稱>/`，在那份上面重新編輯。

（舊版不是這樣：文字寫回 `deck_copy.py`、位置寫進 `overrides.json`，中間隔著
一層 `theme_*.py` 產生物，改完要重跑才看得到。那條路在 phase 1 就拆掉了；主題
檔現在只當 CSS 保存在 `slide_gen/themes/`，直接執行會拒絕。第一次用新版開啟舊
deck 時，`overrides.json` 會自動併進各頁 HTML 並封存成 `.migrated`。）

## 操作

| 動作 | 結果 |
|------|------|
| 點一下 | 選取 |
| 拖曳 | 移動 |
| 拖角落 | 改尺寸 |
| 拖上方圓點 | 旋轉（按住 Shift 每 15° 吸附）|
| 方向鍵 | 微調 1px（Shift 為 10px）|
| **雙擊** | 改文字，點空白處存檔 |
| 插入圖片／影片 | 放進 `assets/` 並加一個可拖曳元素 |
| 刪除 / Delete、Backspace | 刪掉選取的元素（theme 的文字區塊也可以刪），⌘Z 可還原 |
| 還原位置 | 清掉這個元素的位移／尺寸／旋轉，不會刪掉元素 |
| Shift 點擊 | 加選／取消加選 |
| 對齊／均分 | 右欄 ALIGN 區（只選一個時對齊到整張投影片）|
| 格線 | 工具列開關，拖曳與方向鍵都會吸附到 8px |
| 插入文字 | 加一個文字框，雙擊即可編輯 |
| 字體／字級／顏色 | 右欄 TYPE 區 |
| 複製樣式／貼上樣式 | TYPE 區的兩顆按鈕，或 ⌥⌘C／⌥⌘V。把某個元素的文字外觀套到別的元素 |
| 背景動畫 | 右欄選一個 Vanta 效果，14 種，參數即時可調 |
| 背景／前景 | 效果放在文字後面，或蓋在文字前面（底色自動透明、滑鼠可穿透）|
| 互動 | 讓滑鼠直接操作投影片裡的示範（暫停選取），再按一次回到編輯 |
| 播放 | 全螢幕預覽，← → 翻頁、Esc 離開 |
| 打包成單一檔案 | 右欄 EXPORT 區，產出到 `out/` |
| ⌘Z / ⇧⌘Z | 還原／重做 |
| Esc | 取消選取／取消文字編輯 |

右側欄位可以直接輸入數值，比拖曳精準。存檔是自動的（停手 0.4 秒後寫入），
工具列右邊一直顯示目前狀態：未存檔／儲存中／已存檔／存檔失敗。

⌘Z 是快照式的：每個動作前把整頁存一份，還原就是把那份放回去。所以插入、刪除、
改文字、拖曳全部都能還原，而且還原一步不會動到其他步驟的結果。連續按方向鍵微調
會合併成一步，不必按十次 ⌘Z。

左欄的小圓點表示那一頁被編輯過。

**在編輯器外改了檔案，就重新載入頁面再編輯。** 開著的分頁記著的是它載入時的內容，
存檔前會跟檔案的 mtime 對一次；對不上就停止存檔並提示，不會把你在外面做的修改蓋掉。

## 幾個實作上的決定

**編輯數值存在元素身上。** 每個動過的元素會多一個 `data-ed` 屬性，裡面是位移、
尺寸、旋轉這些數值。這樣重新載入時讀得回來，右欄才顯示得出正確的數字。打包時
`build_deck.py` 會把 `data-ed` 拿掉，分享出去的檔案很乾淨。

**位移是疊加在 theme 之上，不是取代。** 第一次選到某元素時會記下它當下的
computed transform 當作 `base`，之後輸出 `transform: <base> translate(...) rotate(...) scale(...)`。
不這樣做的話，theme 裡 `translateY(-50%)` 這種定位會被蓋掉，元素會突然跳位。

**存檔是整份文件序列化，不重新排版。** 瀏覽器的序列化只正規化屬性引號與空元素
寫法，文字節點與縮排原樣保留。所以某一頁第一次存檔會有一筆一次性的正規化 diff，
之後就穩定了，檔案仍然可以手改。

**Enter 換行會被保留。** 瀏覽器在 contenteditable 裡是用 `<div>` 包一層來分行的，
而白名單只留 `<br>`；以前拆掉那層 `<div>` 時連換行一起沒了 —— 編輯中看得到分行、
一離開就併回同一行。現在拆之前會補一個 `<br>`，同時也讓 Enter 直接產生 `<br>`。

**貼上的髒標籤會被清掉。** `contenteditable` 會讓 ⌘B 塞 `<b>`、外部貼上帶
`style="..."`。寫入前只保留白名單（`br` / `span` / `b` / `strong` / `em` / `i`
與 `class` 屬性），否則檔案幾次編輯之後就爛掉。

**注音輸入有處理。** `contenteditable` 在 IME 組字途中就會觸發 `input`，天真的
實作會抓到還沒組完的字。這裡用 `compositionstart` / `compositionend` 擋住，且只在
離開編輯時才送出。

**背景動畫（Vanta）開了就寫進這一頁。** 右欄選效果後，編輯器會把需要的檔案下載到
`slides-*/lib/`（three.js 604KB 或 p5.js 796KB），並在這一頁插入一個 `data-live`
圖層與初始化 script。設定存在圖層的 `data-vanta` 屬性裡，下次打開面板就讀得回來。

底色預設會沿用這張投影片原本的背景色，不會把 theme 的配色蓋掉。哪一個參數算「底色」
每個效果不一樣：多數是 `backgroundColor`，FOG 是 `baseColor`，而 **WAVES 根本沒有
底色參數** —— 整面就是那張波浪，所以接到 `color`，而且會先乘 0.85 補償打光提亮
（直接餵紙色會白掉）。改壞了按「沿用投影片底色」就拉回來。

WAVES 沒辦法跟純色背景完全一致：它本身就有一道光線漸層，一邊亮一邊暗。

CELLS 的 `backgroundColor` 看不到（改了跟預設一模一樣），真正看得到的是
`color1`/`color2` 兩色漸變，所以兩個都接底色、第二個壓到 0.80 讓細胞邊緣有輪廓。
覺得太搶戲的話，把 color2 調亮一點靠近紙色就會變得很淡。

CLOUDS 的天空是 `skyColor`（`backgroundColor` 單獨改看不出差別），沿用底色後就是
你的紙色天空配上原本的雲，效果很好。**CLOUDS2 沒辦法變亮**：它只有 `skyColor`
有作用，而天頂在 shader 裡就是固定往黑色收，所以淺色 deck 用它，上面三分之一會是
深色、深色標題會看不見 —— 它比較適合深色 deck，或當前景層用。
選「前景」時效果會蓋在文字之上，底色自動變透明、滑鼠可以穿透 —— 鳥從標題前面
飛過就是這樣做的。

每一頁用到的函式庫是各自內嵌的，所以每多一頁有效果的投影片，打包檔就多約 600KB。
背景動畫建議只用在封面與章節頁。

**投影片可以跑 JavaScript，但示範內容要放在 `<div data-live>` 裡。**
存檔是把整份 DOM 序列化寫回檔案，所以腳本在執行期產生的節點（Three.js 的 canvas、
終端機輸出、對話訊息…）會被一起寫進原始檔，而且每存一次就多一批。放進 `data-live`
的話，存檔時會換回你寫的那一版，執行期的東西一個都不會進檔案。
容器**外面**被腳本改到的東西仍然會存進去，這是規則的邊界。

打包後的 slide 用 `sandbox="allow-scripts"`：腳本能跑，但拿到的是 opaque origin，
碰不到外層簡報，`localStorage` 也不能用。外部素材要內嵌（Wasm 請用 base64 塞進去、
從 ArrayBuffer 啟動，不要 fetch），真正的終端機或即時 LLM 呼叫需要伺服器或金鑰，
沒辦法放進一個分享出去的單檔 —— 那種請改成播放預錄的過程。

**字體只給「角色」，不給字體名稱。** 右欄的字體選項是標題字／內文字／標籤字，
寫進去的是 `var(--display-font)` 這種變數，不是字體名稱。因為 `build_deck.py` 打包時
是改寫這三個變數（換成內嵌的子集字體），它不會去動元素上的 `font-family` —— 寫死
字體名稱的話，在你機器上看起來對，換一台機器就掉字。

**複製樣式只搬文字外觀，不搬位置尺寸。** 字體、字級、字重、斜體、行高、字距、
顏色、對齊這些會跟著走；位置與大小屬於另一層（`data-ed`），不會被覆蓋。
插入的文字框要長得跟 theme 原本的文字一樣時，選原文按「複製樣式」，再選文字框
按「貼上樣式」就好。

複製時字體會**換回角色變數**再存。computed 的 font-family 是展開後的字體名稱，
直接寫進去打包後會掉字（見上），所以比對過 `:root` 的三個角色變數後，存的是
`var(--display-font)` 這種寫法。

**顏色色票是從這份 deck 的 `:root` 變數讀出來的。** 所以改顏色也還在設計系統裡面，
換 theme 時色票也會跟著換。

**對齊算的是絕對位置，存的是相對位移。** 位移模型是疊在 theme 的 transform 上的
（見上），但對齊要的是絕對座標。作法是從 iframe 讀元素當下的 rect，算出「還差多少」
再加進位移量。所以對齊在任何 theme 排版上都成立，不必先把元素改成絕對定位。

**對齊與吸附保留兩位小數。** 元素常常落在小數位置（標題可能在 left 538.15），
差值取整會讓「置中」差 1px、也會把剛吸附好的元素推離格線。

**右欄顯示的選擇器只是給你看的。** 編輯結果寫在元素自己身上，不靠選擇器定位，
所以 theme 改版導致選擇器失聯的老問題不存在了。

## 已知限制

- undo 只在這個分頁的記憶體裡，關掉分頁就沒了。刪掉元素後如果已經關掉分頁才後悔，
  請從 `.editor-backup/`（每頁第一次改動前的原檔）拿回來。
- 沒有圖層順序 UI；插入元素的 `z-index` 要手動改 HTML。
- 影片預設 `autoplay muted loop`，打包後會被 base64 內嵌，檔案會變很大 ——
  影片建議短。
